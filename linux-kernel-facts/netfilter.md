Netfilter, iptables, and nftables

Netfilter is the kernel framework for packet filtering, NAT, and packet mangling. It provides a set of hooks in the network stack where kernel modules can register callback functions to inspect, modify, drop, or redirect packets. iptables and nftables are userspace tools for configuring Netfilter rules.

---

Netfilter Hooks:

Netfilter defines five hook points in the packet processing path. Every packet passes through some subset of these:

    PREROUTING  → Before routing decision (destination NAT happens here)
         ↓
    Routing Decision: Is this packet for us, or should we forward it?
         ↓                              ↓
    INPUT (for local delivery)     FORWARD (passing through to another interface)
         ↓                              ↓
    Local Process                  POSTROUTING → After routing, before leaving
         ↓                                        (source NAT / masquerade here)
    OUTPUT (generated by local process)
         ↓
    POSTROUTING → Leaving the machine

Packet for this machine: PREROUTING → INPUT → Local Process
Packet being forwarded: PREROUTING → FORWARD → POSTROUTING
Packet from this machine: OUTPUT → POSTROUTING

---

iptables (legacy, still widely used):

iptables organizes rules into tables, and each table contains chains (which correspond to Netfilter hooks):

Tables:
  filter (default): Accept/drop/reject packets. Chains: INPUT, FORWARD, OUTPUT.
  nat: Network Address Translation. Chains: PREROUTING (DNAT), OUTPUT, POSTROUTING (SNAT).
  mangle: Modify packet headers (TTL, TOS, mark). All five chains.
  raw: Bypass connection tracking. Chains: PREROUTING, OUTPUT.

Common iptables commands:

    iptables -L -n -v                    # List all rules in the filter table
    iptables -t nat -L -n -v             # List NAT rules
    iptables -A INPUT -p tcp --dport 22 -j ACCEPT   # Allow SSH
    iptables -A INPUT -p tcp --dport 80 -j DROP      # Block HTTP
    iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT  # Allow replies
    iptables -P INPUT DROP               # Set default policy to drop
    iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE  # NAT for outgoing traffic

    iptables-save > /etc/iptables.rules  # Save rules
    iptables-restore < /etc/iptables.rules  # Restore rules

nftables (modern replacement, kernel 3.13+):

nftables replaces iptables, ip6tables, arptables, and ebtables with a single unified framework. It is the default on RHEL 9+, Debian 11+, and Fedora.

Key differences from iptables:
  - Single tool (nft) replaces four separate tools.
  - Tables and chains are user-defined (you name them whatever you want).
  - Rules use a more readable syntax.
  - Supports sets and maps natively (list of IPs/ports to match, without needing ipset).
  - Better performance for large rulesets (uses a compiled bytecode VM in the kernel).

Basic nft commands:

    nft list ruleset                      # Show all rules
    nft add table ip my_filter            # Create a table
    nft add chain ip my_filter input { type filter hook input priority 0\; }
    nft add rule ip my_filter input tcp dport 22 accept
    nft add rule ip my_filter input tcp dport 80 drop
    nft add rule ip my_filter input ct state established,related accept

    nft list ruleset > /etc/nftables.conf  # Save
    nft -f /etc/nftables.conf              # Load

Sets (match multiple values efficiently):

    nft add set ip my_filter blocked_ips { type ipv4_addr\; }
    nft add element ip my_filter blocked_ips { 10.0.0.5, 10.0.0.6 }
    nft add rule ip my_filter input ip saddr @blocked_ips drop

Connection Tracking (conntrack):

Netfilter's connection tracker (nf_conntrack) maintains a state table of all active network connections. Each packet is classified as:

    NEW:         First packet of a new connection (SYN for TCP).
    ESTABLISHED: Packet belongs to an already-established connection.
    RELATED:     New connection related to an existing one (FTP data channel, ICMP error).
    INVALID:     Doesn't belong to any known connection (often dropped).

This is what allows the common "accept ESTABLISHED,RELATED + drop everything else" rule pattern: you allow replies to connections you initiated without explicitly allowing inbound traffic.

    conntrack -L                         # List all tracked connections
    conntrack -C                         # Count of tracked connections
    cat /proc/sys/net/netfilter/nf_conntrack_max   # Max tracked connections (default 65536)
    cat /proc/sys/net/netfilter/nf_conntrack_count # Current count

If nf_conntrack_count hits nf_conntrack_max, new connections are dropped with "nf_conntrack: table full, dropping packet" in dmesg. Fix by raising the max or optimizing the timeout:

    sysctl -w net.netfilter.nf_conntrack_max=262144
    sysctl -w net.netfilter.nf_conntrack_tcp_timeout_established=3600

NAT (Network Address Translation):

SNAT (Source NAT): Changes the source IP of outgoing packets. Used when a private network shares a single public IP.
    iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j SNAT --to-source 1.2.3.4

MASQUERADE: Like SNAT but automatically uses the outgoing interface's current IP. Preferred when the IP is dynamic (DHCP):
    iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

DNAT (Destination NAT): Changes the destination IP of incoming packets. Used for port forwarding:
    iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.100:80

---

firewalld (RHEL/Fedora/CentOS):

firewalld is a userspace daemon that manages nftables (or iptables) rules through zones. It provides a higher-level interface than raw nft commands.

    firewall-cmd --list-all                       # Show current zone rules
    firewall-cmd --add-service=http --permanent   # Allow HTTP
    firewall-cmd --add-port=8080/tcp --permanent  # Allow port 8080
    firewall-cmd --reload                          # Apply changes

Zones (public, internal, trusted, etc.) define default policies for groups of interfaces.
